# 环境与凭据

## 环境

环境等于镜像 digest 加工作区。容器里除了工作区和缓存目录，其余都是只读的。这样换一台机器，只要拉同一个 digest、还原同一个工作区，就是同一个环境。agent 在容器里用什么语言和工具都不限。

- **定义**：项目里放一个 `.harness/env.toml`，或者直接复用 `devcontainer.json`。里面写镜像名，并用 digest 锁定版本。镜像要同时构建 arm64 和 x86-64 两个架构，因为 mac 是 arm64，pc 是 x86-64。
- **镜像仓库**：MVP 用 GHCR。节点按 digest 拉取。
- **运行时**：Linux 节点用 rootless podman。mac 上先起一个 Linux VM（Lima、OrbStack 或 Apple containerization），harnessd 跑在 VM 里面，整个 VM 就是一个节点。
- **挂载**：
    - `/workspace`：项目目录，参与检查点同步。
    - `/cache`：cargo、npm 等缓存，每台节点各自保留，不同步。
    - 根文件系统只读，`/tmp` 是 tmpfs。
- **浏览器**：镜像里预装 Chromium，见[浏览器](03-browser.md)。
- **预热**：节点成为某个会话的热备时，就先拉好镜像。这样接管时不用等下载。
- **资源限制**：每个会话一个容器，CPU 和内存上限写在 `env.toml` 里。
- **agent 想装新依赖时**：根文件系统是只读的，直接 `apt install` 会失败。所以提供一个 `env_add_package` 工具：它改 `env.toml` 并重建镜像。改动本身在工作区里，会随检查点同步。

## 节点入池与凭据同步

凭据只在节点之间点对点同步，Cloudflare 上连密文都没有，只有节点的证书公钥。新机器必须由你在客户端上批准，才能拿到密钥。

### 身份

- 每个节点第一次启动时，生成一对 ed25519 密钥（签名用）和一对 X25519 密钥（加密用）。MVP 阶段用权限 0600 的文件保存，以后可以换成 TPM 保存。
- 节点和 coordinator 之间全部走 mTLS，节点证书的有效期暂定 90 天。
- 节点在名册里上报自己的能力（如显卡型号、显存），供以后的[端侧模型服务](06-local-models.md)调度用。MVP 只预留字段。

### 入池流程

1. 在新机器上执行 `harnessd join https://<coordinator>`。终端会显示一个 6 位配对码，以及公钥指纹。
2. coordinator 把这个请求显示在客户端的待批准列表里。你核对配对码和指纹后批准。
3. coordinator 签发节点证书。证书里包含公钥、名字、有效期，以及允许使用的凭据范围。
4. 一个在线的老成员节点用新节点的 X25519 公钥，把池的数据密钥（DEK）重新包一份。coordinator 全程接触不到明文的 DEK。

客户端第一次启动时走同样的配对流程，拿到自己的密钥。

### 凭据库

- 每条凭据单独用 DEK 加密（age 格式），按版本号在节点之间点对点同步。新节点入池后，从任意一个在线成员那里拉取。
- 任务在 `env.toml` 里声明要哪些凭据，比如 `secrets = ["GITHUB_TOKEN", "ANTHROPIC_API_KEY"]`。节点只在启动容器时，把这几条解密后注入进去。
- 新增或修改凭据，可以在任意成员节点的 CLI 里做；也可以在客户端上做，在本地加密后交给一个在线节点。
- 浏览器状态文件同样用 DEK 加密、点对点同步。

### 移除节点

吊销它的证书，生成新的 DEK，只为剩下的节点重新包装。但它已经解密过的凭据和浏览器登录状态只能当作已经泄露。所以客户端会列出这个节点用过哪些凭据、登录过哪些站点，提醒你去上游换掉它们。
