# 端侧模型服务

本地模型是[服务模型](10-services.md)里的**无状态服务**：不属于某个会话，哪台节点能跑就放在哪台，所有会话都能调用。包括两类：

- **本地 LLM**：如 Qwen 系列 0.8B–4B 的小模型，用于离线兜底和杂活。
- **辅助模型**：语音转文字、文字转语音、AI 绘图等。

## 阶段

| 阶段 | 内容 |
| --- | --- |
| MVP | 模型提供方可以配成本机的 Ollama 或任意 OpenAI 兼容端点（goose-providers 已支持），单机离线时也能用小模型。节点名册预留能力字段，容器里预留本地接口地址 |
| MVP 后 | 统一模型服务：跨节点放置与路由、按任务路由模型、辅助模型、显存调度 |

## 本地 LLM 的用法

小模型能力有限，4B 这个量级多步调用工具不可靠，所以不当主力，写代码这类长任务仍交给云端大模型。适合它们的是：

- **离线兜底**：云端不可用（断网、额度用完）时自动降级到本地模型，客户端明确提示"当前用的是降级模型"。
- **杂活**：对话压缩时做摘要、给会话起标题、给工具输出分类、语音识别后的文本整理。0.8B 这一档用 CPU 也能跑，单机时也能用上。

**按任务路由**（MVP 后）：设置里配好"哪类任务用哪个模型"，例如：

| 任务 | 首选 | 降级 |
| --- | --- | --- |
| agent 主循环 | 云端大模型 | 本地 4B（提示降级） |
| 对话压缩、起标题 | 本地小模型 | 云端模型 |
| 语音识别后整理 | 本地 0.8B | — |

## 辅助模型

原因在硬件：每台机器能跑的模型不同（例如 pc 有 NVIDIA 显卡，mac 节点是 Linux VM、用不到 Apple GPU）；模型文件动辄几 GB，不适合跟着检查点复制。

1. **节点上报能力**：入池时上报硬件（显卡型号、显存）和能跑的模型，写进节点名册。
2. **统一接口**：每个容器里提供一个本地地址，接口仿照 OpenAI 的格式（对话补全、语音转文字、文字转语音、生成图片）。很多现成工具认这个格式，agent 用什么语言调都行。
3. **harnessd 转发**：容器里的请求先到本机 harnessd，再经 iroh 转给装了该模型的节点。会话跑在 mac 上也能用 pc 的显卡。
4. **推理后端用现成的**：例如 Ollama / llama.cpp 跑 LLM，whisper.cpp / sherpa-onnx 做语音转文字，Piper / Kokoro 做语音合成，stable-diffusion.cpp / ComfyUI 画图。这一层不要求 Rust，harnessd 只负责启动、停止和转发。
5. **模型文件按内容寻址**：属于"仅本地缓存"。用 hash 标识，第一次用时从 Hugging Face 下载，或从池里已有该文件的节点点对点拉取（iroh 支持大文件传输）。不进检查点。
6. **显存调度**：消费级显卡一次只放得下一两个模型，请求排队，闲置一段时间自动卸载。

## 和替补的关系

模型调用不改变状态、不涉及外部操作，属于"内部操作"，重做没有代价：

- 装模型的节点掉线，请求换一台有能力的节点重试；没有能接手的，就报错给 agent（或按路由表降级）。
- 生成的图片、音频写进工作区，随快照同步；单个文件超过 50 MB 时跳过，规则照旧。

## 取舍

想用 mac 的 GPU，模型服务必须直接跑在 macOS 上，不能放在 Linux VM 里，这会打破"只支持 Linux"的约定。先只让 Linux 节点提供需要显卡的模型；小模型用 CPU 跑不受影响。
