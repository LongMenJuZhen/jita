# 会话与替补

## 会话日志与工作区的一致性

绑定方式：工作区快照的 hash 直接写进会话日志，快照对象永远比引用它的会话提交先到达热备。因此副本上任何一个 seq 都能还原出对应的文件，不需要另外维护映射表。浏览器状态用同样的方式绑定，见[浏览器](03-browser.md)。

### 每次工具调用结束时如何打检查点

1. 工具返回后、结果提交之前，harnessd 用一个隐藏的 git index（`GIT_INDEX_FILE`，不碰用户自己的 index）把工作区写成一个 tree，得到 hash `T`。
2. 用 git 协议把 `T` 缺少的对象直接推给每个热备，ref 为 `refs/harness/<session>/latest`。文件没变时 `T` 不变，什么都不用传。
3. 把工具结果和 `workspace = T` 写进同一个会话批次，一次落盘，天然原子。
4. 会话批次经 iroh 推给每个热备。顺序规则是"先推快照，再推引用它的批次"。热备收到后，向 Cloudflare 上报自己的副本 seq。

这样，最近一条带 `workspace` 的记录就是检查点。

### 快照里包括什么

- 包括：已跟踪的文件，以及没有被 git ignore 的未跟踪文件，和 Delta 的范围一致。
- 不包括：被 git ignore 的文件（`node_modules`、`target/` 等），这些在新节点上由环境重新生成。
- 单个文件超过上限（暂定 50 MB）时跳过并告警。
- 仓库自己的 `.git` 目录（分支和提交历史）单独同步：每次检查点记录当前的 HEAD 和分支，仓库对象一起推送。

### 还原

热备接管时，先把工作区检出到最近检查点的 `T`，恢复 HEAD 和分支，再从对应的 seq 恢复 agent 循环。检查点之后没做完的那个工具调用按下文「外部副作用与重做」的规则处理，最多重做一次。

## 租约与自动替补

只有 coordinator 能发租约，租约过期后大约 30 秒内由热备接管。两道保险防止旧 driver 污染数据：第一道，失联的 driver 不再做外部副作用；第二道，热备拒收旧 epoch 的批次，旧副本拆成新会话。

| 参数 | 暂定值 | 说明 |
| --- | --- | --- |
| 心跳间隔 | 5 秒 | driver 和热备都发，心跳里带上副本的 seq |
| 租约 TTL | 20 秒 | 由该会话的 SessionDO 用服务端时钟计时，到期由 alarm 触发回收 |
| driver 自我隔离 | 15 秒 | driver 从发出最后一次成功续约起计时，超时后暂停外部副作用 |
| DO 重启或迁移宽限 | 5 秒 | 到期时间已持久化，重启不影响租约；只是重启时恰好已过期的租约，要多等 5 秒再转交，让 driver 有机会续上 |
| 接管人选 | 副本最新者 | 把租约交给上报 seq 最高的热备；它如果落后于其他节点，先从那里追平再开始写 |

### 自动替补的步骤

1. SessionDO 发现会话 S 的租约在 20 秒内没有续约，由 alarm 触发。
2. 挑一个热备：在线、镜像已拉好、持有任务需要的凭据。候选中选上报副本 seq 最高的。
3. **唯一的原子步骤**：在该会话 SessionDO 的一个 SQLite 事务里，把 epoch 加 1、换持有人、记录交接事件。事务提交之前，对外什么都不变。
4. 新 driver 收到租约后：把新 epoch 告诉其他热备，它们从此拒收旧 epoch 的批次。如果自己的副本不是最新的，先从其他节点追平。然后把工作区还原到最近检查点，启动容器，恢复浏览器，恢复 agent 循环。这些完成之前它不写任何东西；中途失败就释放租约，回到第 2 步。
5. agent 循环重试被打断的回合，任务继续。SessionDO 通知客户端"S 已由 pc 接管"。

接管时**不走** goose-agent 的取消流程（它会把未完成的工具调用标成"被中断"），而是直接从日志加载，让未完成的调用按重做规则处理。

**丢失多少**：只会丢旧 driver 已经在本地提交、但还没推到任何热备的那一点。每次提交后都会立即推送，所以通常是秒级。这部分不会消失，而是保留在拆出来的新会话里。

### 旧 driver 回来了怎么办

- 它的续约会被 SessionDO 拒绝，推给热备的批次也会因为 epoch 过期被拒。harnessd 停掉本地的 agent 循环。
- 如果它有没推出去的提交，就保留为"分叉自 S@seq"的新会话。客户端上会标出来，由你决定丢弃还是继续。
- 之后它从新 driver 重新追平，变成热备。

**主动交接（零丢失）**：比如 mac 合盖前，driver 做完当前工具调用、传完所有批次，再释放租约。coordinator 立即转给指定节点，不用等 TTL。

**driver 联系不上 coordinator 时**：driver 分不清是 coordinator 挂了，还是自己被断网了。所以它继续做内部工作（调模型、改文件），但外部副作用要等续约成功才放行。就算最后发现已经被接管，损失也只是一段白做的工作，不会重复 push 或重复发消息。

**副本确认**：外部副作用执行前，要求至少一个热备已确认收到当前 seq。这样替补后，这条外部操作既不会丢，也不会重做。只有一台节点在线时没有热备可以确认，外部副作用照常执行，但客户端上会提示"当前没有副本"。

## 外部副作用与重做

工作区里的操作重做一次没有代价，因为工作区已经回到了检查点。真正要管的是对外的操作。规则是：先记下要做什么，再去做；恢复时如果只有记录、没有完成标记，就先去核对再决定。

| 类别 | 例子 | 恢复时怎么处理 |
| --- | --- | --- |
| 内部 | 改文件、编译、跑测试、调端侧模型 | 直接重做 |
| 外部可核对 | `git push`、开 PR、发 GitHub 评论 | 先去远端查。提交是否已经在远端分支上？同一个 head 分支的 PR 是否已经存在？评论里带隐藏的幂等键，用来查重。没做过才重做 |
| 外部不可核对 | 发聊天消息、调用有副作用的第三方 API、浏览器里的点击和提交 | 不自动重做，通知客户端让你确认；浏览器操作交给 agent 先看页面再决定（见[浏览器](03-browser.md)） |

### 怎么拦住外部操作

镜像里的 `git` 和 `gh` 替换成一层薄包装。遇到 push、建 PR、发评论这类外部子命令时，包装先通过 unix socket 问 harnessd：

1. 租约是否有效？无效就阻塞等待，或者报错。
2. 在会话里提交一条意图记录，内容是幂等键加上命令。
3. 执行。
4. 提交一条完成记录。

agent 自带的外部工具和 MCP 工具，在 agent 循环里套上同一套流程。

**已知缺口**：容器里的任意 `curl` 拦不住。MVP 接受这个风险，以后可以给容器加出口白名单。
