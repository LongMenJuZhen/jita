# 客户端与控制面

客户端是原生 Rust 桌面程序（egui + wgpu），不套浏览器。第一次启动时像节点一样配对，拿到自己的密钥，之后作为 iroh 节点直接连到 driver 或热备。手机端暂不做。界面长什么样见[界面设计](09-ui.md)。

会话内容不在 Cloudflare 上，所以客户端直接连一个在线节点（driver 或热备），打洞失败时才经 SessionDO 中继。数据端到端加密，中继只转发、不落盘。driver 掉线时，可以从热备看到掉线前的最后状态。所有节点都离线时，只能看到会话列表和各节点最后上报的 seq。

## 看

- 池概览：哪些节点在线、健康状况、各自在 drive 或热备哪些会话。
- 会话列表：状态（运行中、等你回复、失败、已分叉）和当前 driver。
- 会话详情：对话和工具输出实时滚动，经 iroh 从副本推送。延迟通常是秒级。
- 浏览器画面：实时查看会话容器里的浏览器，必要时亲手操作（如登录、验证码），见[浏览器](03-browser.md)。

## 指示

- 发消息：可以是新的输入，也可以是对当前运行中途的纠正。
- 停止当前回合。
- 批准或拒绝待确认的工具调用。
- 把会话主动交接到指定节点。
- 处理分叉出来的会话：丢弃或者继续。
- 批准新节点入池。
- 管理凭据。

## 指令怎么送到 driver

客户端给每条指令分配一个 `requestId`，发给 driver。driver 先存进本地收件箱，再按 `requestId` 写进会话日志；重复的 `requestId` 只保留第一次，所以重发不会重复执行。如果正好在交接、暂时没有 driver，SessionDO 先暂存这条加密的指令，新 driver 启动后首先取走它。

## 通知

由 SessionDO 通知客户端，桌面上显示为系统通知，正文只写事件类型，不带会话内容。只通知需要你关注的事：agent 提问或请求批准、任务完成、任务失败、发生替补、有新节点申请入池、浏览器需要人工登录。
