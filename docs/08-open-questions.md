# 未决问题与风险

最大的未决问题是 agent 的手感：系统提示词、工具描述、编辑工具的容错、压缩的触发时机。代码量不大，调好要花时间。先照着 goose、pi 和 Hermes 的提示词与工具设计做，再用实际任务对比着调。

- [ ] **workers-rs 的支持程度**：确认它对 Durable Objects 的 SQLite 存储和 alarm 支持到什么程度。不够用的话，coordinator 退回 TypeScript。
- [ ] **GDK 的接管语义**：goose-agent 在 Stop 时会给未完成的工具调用填上"被中断"。替补时不走它的取消流程，直接从日志加载，让未完成的调用重做或核对。M0 实测。
- [ ] **GDK 还是 alpha**：锁定版本（目前 0.1.0-alpha.13），升级前先跑一遍 M0 的 kill 测试。
- [ ] **时钟**：定时任务的截止时间按墙上时钟存，跨机器接管时有偏差，可能提前或延后触发。MVP 要求所有节点开 NTP，并在心跳里上报时钟偏差。
- [ ] **依赖 Cloudflare**：只在多机时需要，单机不依赖。已决定接受。DO 不可用时，正在跑的任务继续跑，但不能替补，也不能做外部副作用。不会丢数据：Cloudflare 上本来就没有会话内容。
- [ ] **大仓库的快照开销**：每次工具调用后都要扫一遍工作区。对大仓库可能太慢，需要用 fsmonitor 之类的增量机制。先在实际仓库上测一下。
- [ ] **凭据外泄**：容器里的 agent 本身就能读到注入的凭据和浏览器登录状态。MVP 只做按任务声明注入，不防 agent 自己泄露。
- [ ] **浏览器登录失效**：cookie 过期，或站点因 IP、设备指纹变化让登录失效。接管后检测到就提示人工重新登录。
- [ ] **和 Radius 重叠**：如果 Radius 出了自部署版本，或者加上了自动接管，就重新评估 coordinator 还要不要自己做。
- [ ] **只有一台节点在线**：这时没有任何副本，硬盘坏了就会丢数据，也无法替补。可选的兜底：把端到端加密的备份放到 R2 或 NAS，云上只有密文。
- [ ] **组网**：iroh 打不通时走中继，默认是 n0 公司的公共中继，也可以自建；备选方案是 Tailscale。先实测 mac 的 VM 和 pc 之间能不能直连。
- [ ] **共享协议 crate**：coordinator 和 harnessd 都用 Rust，协议类型放在一个共享 crate 里两边直接用。coordinator 编译成 WASM，所以这个 crate 不能依赖 tokio 这类原生运行时。
- [ ] **免费额度**：Cloudflare 上只剩租约、心跳和中继，用量很小。客户端大多直连节点，中继只在打洞失败时用，仍要对照官网额度估算一下。
- [ ] **数据库服务指什么**：是 agent 开发项目时用的数据库（属于会话环境，随会话同步），还是你自己的跨设备数据（笔记、记忆、向量库，独立的有状态服务）？见[服务模型](10-services.md)。
- [ ] **单机升级为多机**：把本地仲裁的 epoch 和名册迁到 coordinator 时，正在跑的会话怎么处理（先暂停再迁，还是在线迁）。M3 定。
- [ ] **本地小模型的质量**：0.8B–4B 能可靠完成哪些杂活（摘要、起标题、分类），降级跑 agent 主循环时能做到什么程度。M0 接入后用实际任务测。
- [ ] **服务接口何时提炼**：MVP 只有一个有状态服务；第二个出现时（多半是数据库）再把服务契约提炼成 trait，避免过早抽象。
- [ ] **并行和热备抢机器**：池里的机器既当热备又跑子会话，忙的时候谁当热备、子会话放哪里，需要一个调度策略。
- [ ] **权限模型**：哪些操作必须由人批准、管理者 agent 能做什么不能做什么，要列成清单。原则：agent 不能批准自己或下属 agent 的外部操作。
- [ ] **减少往返的工具形态**：是否提供"让模型写脚本一次做完多件事"的工具（code mode），它和外部操作拦截怎么配合。
- [ ] **托管工具的可行性**：以后台 Godot 提供 MCP 为例，原版能否无界面启动并稳定提供 MCP；不行再考虑 fork。
- [ ] **手机端**：客户端先只做桌面。手机端做不做、只做轻量控制还是也看 3D，后面再定。
- [ ] **端侧模型与 macOS**：用 mac 的 GPU 需要在 macOS 上原生运行模型服务，与"只支持 Linux"冲突。先只让 Linux 节点提供。
