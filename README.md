# Jita

Jita 把自己的设备组成一个 agent 环境池。只有一台设备时功能完整可用；有多台时，agent 在池里跑起来像在一台机器上，任一台掉线，另一台在约 30 秒内从最近的检查点接着跑。你在原生客户端上随时看进度、下指令。

## 一句话架构

项目分两层：**框架**负责在设备之间同步和调度，**服务**干具体的活（agent 会话、本地模型、数据库等）。

- **仲裁者**：只管"谁能写"——租约、节点名册。单机时内置在 harnessd 里；多机时是 Cloudflare 上的 coordinator（Workers + Durable Objects，Rust 编译为 WASM），同一份代码。不存任何会话内容。
- **harnessd**（每台节点一个 Rust 二进制）：框架核心（名册、租约、点对点复制、放置、路由、容器、凭据）加上各个服务，第一个服务是 agent 会话（基于 goose 的 GDK）。
- **客户端**（原生 Rust，egui + wgpu）：作为 iroh 节点直连池里的节点。

会话日志、工作区快照、浏览器状态和凭据密文只在你自己的机器之间点对点同步，不上云。
